## F10-20 — Docker / remote sandbox stays optional, not a hard dependency

The local core has no Docker dependency at all: the workspace manifests
declare no Docker runtime, `infrastructure/docker/README.md` records that the
Docker sandbox is intentionally deferred (reserved placeholder only), and the
sandbox-host package is the self-contained Windows-native host documented in
`docs/security/sandbox-host.md` — it fails closed (`unavailable`) outside
Windows or without its FFI dependency without affecting the rest of the
evidence pipeline (`packages/sandbox-host/tests/sandbox-host-fail-closed.test.ts`:
"reports unavailable on non-Windows platforms without spawning", "reports
unavailable when the FFI layer cannot load, without spawning").

The in-process path needs no host at all: the default proof adapter is the
pure SHA-256 content-integrity adapter in `@arena/debate-engine`
(`packages/debate-engine/tests/sandbox-adapter.test.ts`), and the
`SandboxAdapter` port keeps network, filesystem, process execution, and
secrets as explicit server-side capabilities, denied by default
(`packages/types/src/sandbox-adapters.ts`,
`packages/debate-engine/tests/sandbox-adapter.test.ts`).

Conclusion: Docker or a remote sandbox is an optional future adapter
(F10-20's own wording); nothing in the local core requires it.

## F10-24 — Sandbox denial, timeout, malformed output, and cleanup without hanging the match

Exact supporting suites (real Windows host tests, no Docker):

- `packages/sandbox-host/tests/sandbox-host.windows.test.ts` — denial before
  spawn is covered in the fail-closed suite; wall-clock watchdog kill
  (`timed_out`), output-cap kill (`resource_exhausted`), malformed-output
  classification, mid-run cancellation (`cancelled`, no orphans),
  whole-tree termination, verified cleanup receipts, and stale temp-dir sweep
  are proven here.
- `packages/sandbox-host/tests/sandbox-host-fail-closed.test.ts` —
  capability denial ("denies when process.spawn is not granted, without
  spawning"), preflight fail-closed behavior, oversized/malformed input
  rejection before spawn, and cleanup-failure reporting
  (`cleanup_failed` with an unclean receipt).
- `packages/sandbox-host/tests/worker-protocol.test.ts` — strict
  request/response bounds so malformed worker output can never be trusted.
- Contract-level denial semantics:
  `packages/debate-engine/tests/sandbox-adapter.test.ts` (deny-by-default
  capabilities, safe denial/result shapes, terminal results always carry a
  cleanup receipt) and `packages/debate-engine/tests/challenge-runner.test.ts`
  ("classifies provider errors as failed with a safe message" — a sandbox or
  adapter failure terminates the challenge without hanging or altering the
  match verdict, per F10-14).

Conclusion: F10-24 is complete on the strength of the `@arena/sandbox-host`
test suites recorded on 2026-09-11 (see also `docs/security/sandbox-host.md`).
